# Source Desktop New submenu — bounded React port

**Pinned source:** `codersachin99/legacy-win7@4e63290d783009e1293433c6ccf252abba9c1187`, `src/modules/system/main.js` desktop background context menu. The source exposes four New choices in this order: Folder (`new-folder`), Shortcut (`new-shortcut`), Rich Text Document (`new-richtext`), and Text Document (`new-text`). Original Shortcut calls `OpenWindow("shortcut")`, which is not yet an implemented React app.

**Implementation:** `packages/ui/src/desktopCreate.ts` operates only on the active `sourceFilesystemRuntime.snapshot().desktopPath`, never a separate mock catalog. Shared VFS `createFile` refuses pre-existing filenames and directories; source-style numbered defaults are checked case-insensitively, with storage-level EEXIST handling if another creator wins. The source shortcut serializer `sourceShortcut(program)` writes JSON `{exe,icon}` to `.lnk` in Guest Desktop. Only pinned installed source programs selectable from the currently migrated React app registry are enabled in the interim wizard. Names are checked against Windows illegal/control/reserved names and a 30-char basename. No arbitrary command execution, host filesystem creation or overwrite is possible through this path.

**UI:** background right-click → New → Folder/Shortcut/Rich Text Document/Text Document. Newly created basic entries are offered inline rename, with VFS change subscribers updating Explorer and other open instances; shortcuts use a keyboard-accessible form with program and visible name. TXT opens in native Notepad, .lnk opens a migrated source program. The RTF file gets a syntactically valid minimal document; WordPad/editor association is *not* migrated.

**Tests:** `desktopCreate.test.ts` verifies create-only writes, default names/collision handling, source JSON and rejected input. `desktop-create.spec.ts` covers Windows 7 Guest desktop/mobile New menu, inline filename edit, reload persistence, TXT association, Calculator .lnk launch and duplicate rejection. CI verification not yet completed at creation of this note.

**Not included:** the original dedicated shortcut wizard UI, full program browsing or external target paths, exact naming/locale styles/screenshots, source-format Rich Text editor, all desktop drag/drop behavior, context-menu layout parity, and non-Guest/multiuser drives. Module tracker stays `in-progress`.
