# Guest Desktop → Explorer file drag/drop — bounded source migration

**Original source references:** \`legacy-win7/src/modules/system/main.js\` owns the pointer-driven desktop shortcut selection/positioning gesture with a 4-pixel threshold; \`legacy-win7/src/modules/apps/computer.js\` owns the Explorer drop parsing and file operations. The original source desktop binds external file drops through \`_parse(...,desktopPath)\`, while Explorer has destination-specific drop handling. Cross-window desktop-to-Explorer internal file transfer is an integrated React shell feature based on those existing source actions, **not** a claim that the original Vue modules implement this exact pointer bridge.

**Implementation:** \`packages/ui/src/desktopExplorerDrop.ts\` locates the topmost visible Computer/Explorer folder under a desktop pointer, taking an actual file-backed folder row over the current contents area. It ignores obscured targets, Recycle Bin windows, other application windows, malformed paths and non-folder controls. \`DesktopIcons.tsx\` continues using the original pointer gesture and selection; after the 4px threshold it starts a shared \`fileDragSession\` token for real Guest file entries, highlights the eligible destination and performs a shell transfer on pointer release. Dropping over an invalid or obscured window does not reposition desktop icons behind that window. System icons are never accepted as file sources. Ctrl/Meta held on release copies instead of moving; normal release moves.

**Filesystem/data safety:** \`FileDragSession.drop\` routes through \`transferFiles\`, which validates the real mounted Guest destination and all sources, rejects missing source paths, same-directory or nested-folder transfers and destination collisions, and refuses to overwrite existing user content. The shared VFS publishes results to the Desktop, Explorer and other mounted apps. The desktop's file clipboard is untouched. On abort/cancel/blur the drag token and transient Explorer highlight are cleared. A batch is preflighted before mutation; storage quota failure atomic rollback of *multi-item copy/move* is not yet implemented and remains a separate work item (Recycle Bin batch trash is atomic).

**Coverage:** \`desktopExplorerDrop.test.ts\` tests topmost hit filtering, source session move/copy validation, collision and nested-directory rejection. \`tests/e2e/desktop-explorer-drop.spec.ts\` covers desktop/mobile Chromium pointer move to current Explorer folder, Ctrl-copy and collision, group drop on a named folder row, and same-directory guard. Legacy desktop Recycle Bin icon drops and free icon repositioning must remain unchanged.

**Status:** code and tests pushed. CI pending. Full Explorer→Desktop native browser drag and host upload/drop, dragging files out of sandbox, touch accessibility, exact original drag-ghost styling and all source visual screenshots remain separate parity work. The original desktop and Computer modules remain in progress; draft PR unmerged.

**Mobile failure investigation:** the source Guest icon state and transfer logic were correct, but the first two narrow mobile blank-pane drag tests used a pointer origin at x = −44 after Explorer navigation scrolled the *entire* horizontal document. Actions [43210729342](https://github.com/codersachin99/windows-os/actions/runs/43210729342) and [43211904291](https://github.com/codersachin99/windows-os/actions/runs/43211904291) diagnosed this; the latter run's downloadable Playwright trace/screenshot confirmed the offscreen origin. The fix lives in generic shell `packages/engine/src/index.ts` source-positioned window bounds, unit tests and `windows7.css` rather than weakening VFS checks. Pending full rerun.
